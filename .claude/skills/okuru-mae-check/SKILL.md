# 送る前チェック

## これは何？

メールを大勢に送る**直前**に、事故のもとがないか確認します。

このチェックリストは、**実際に起きた事故**から作られています。
「気をつける」では防げません。**手順として機械的に踏んでください。**

## ★絶対ルール：テスト送信 → 実機で目視

例外はありません。

1. **配信先を自分1人だけに絞って、テスト送信する**
2. **実際にメールを開いて、自分の目で見る**
3. OKなら配信先を全員に戻して、本送信

### 実機で見るポイント
- 本文がちゃんと表示されているか（**空になっていないか**）
- HTMLのタグがそのまま見えていないか
- 文字化けしていないか
- **リンクを実際に押してみる**
- 差し込み（お名前など）が崩れていないか

### なぜ画面の確認だけではダメなのか

過去に起きた事故の原因は、毎回ちがいました。

- HTMLで書いた本文を、テキスト形式で送ってしまい**タグが丸見え**になった
- 本文を書く欄を間違えて（メモ欄に入れて）、**本文が空のまま15人に届いた**
- テスト送信では正しく届くのに、本番だけ空になった

原因が毎回違うので、決まった項目をチェックするだけでは取りこぼします。
**実機で目で見ることだけが、唯一の歯止めです。**

## チェックリスト

### 本文
- [ ] 本文が空でないか（プレビューに全文が出ているか）
- [ ] タグが見えていないか
- [ ] 絵文字が消えていないか（**テキスト形式のメールでは絵文字が丸ごと消えます**。顔文字は残ります）
- [ ] 差し込みが正しく置き換わるか

### リンク
- [ ] **URLを実際に開いた**か
- [ ] 申込先が正しいか
- [ ] URLがメール本文に入っているか（LINEやチャットだけで案内していないか）

### 宛先
- [ ] 送る相手が正しいか（**未入金の人に、入金者向けの案内を送っていないか**）
- [ ] テスト用のアドレスが残っていないか

### 決まりごと
- [ ] 配信解除リンクが末尾にあるか（メルマガの場合は必須）
- [ ] 問い合わせ先が、**返信できるアドレス**になっているか
- [ ] 送信専用アドレスから出すなら「このメールには返信できません」と書いたか

### 日時
- [ ] 日付の曜日が合っているか
- [ ] 予約配信の時刻が正しいか

## 送ったあと

配信履歴を開いて、本文がちゃんと記録されているか確認します。
ここが空なら、本文が送られていません。**すぐ気づけば再送できます。**

## 自分用に直すところ

- 使っている配信システムの名前と、確認する画面の場所
- テスト送信先のアドレス
- 自分の署名・フッターの決まり
