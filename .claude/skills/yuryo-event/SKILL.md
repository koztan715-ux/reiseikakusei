# 有料イベントの一式を組む

## これは何？

有料のセミナーやイベントを開くとき、
**申込 → 決済 → 完了メール → 領収書 → リマインド → 当日**
までの仕組みを一式そろえます。

バラバラに作ると、必ずどこかが抜けます。このスキルは**抜けやすいところ**を知っています。

## こう言ってください

```
〇月〇日の有料セミナーの準備をしてください。
価格は△△、定員は□人、オンラインです。
```

## そろえるもの（順番）

| # | やること | 抜けやすさ |
|---|---|---|
| 1 | 募集ページ（LP）を作る | |
| 2 | 申込フォームを作る | |
| 3 | 決済を設定する | ★金額の設定し忘れ |
| 4 | 申込完了メール | |
| 5 | **領収書メール** | ★★忘れやすい |
| 6 | **決済リマインド**（申し込んだが払っていない人向け） | ★★★最も忘れる |
| 7 | 前日・当日のリマインド | |
| 8 | 登録完了ページ | |

## ★絶対に守ること

### 1. 領収書は、申込完了メールと同時に送る
あとから「領収書ください」と個別に言われるのは、**全部あとから手作業**になります。
申込完了と同じタイミング（0分後）に、領収書メールも自動で送る設定にしてください。

### 2. 未入金の人に、当日の参加URLを送らない
申し込んだだけで払っていない人に参加URLを送ると、**払わないまま参加できてしまいます**。
未入金の人へ送るのは、**決済のリンクだけ**です。

### 3. 決済リマインドを必ず設定する
「申し込んだけど決済画面で離脱した」人は、必ず一定数います。
リマインドを送るだけで回収できます。**決済が終われば自動で止まる**設定にしてください。

### 4. 過去のイベントから複製したら、必ず全部見直す
これが**最大の事故のもと**です。

前回のイベント設定をコピーして使うと、
**前回の日時・前回の参加URL・前回の金額**がメールのどこかに残ります。

- すべてのメールを横断して、**前回の情報が残っていないか検索する**
- 特に「イベントの〇日前に送る」タイプのリマインドは見落としやすい
- テスト送信して、実機で全部目を通す

実際に、前回のオンライン会議URLが残ったまま配信された事故が起きています。

## 決済について

- 決済の方法は1つに統一する（システムを混ぜると、集計も領収書もややこしくなります）
- **決済方法を切り替えると、金額が0円にリセットされることがあります。** 切り替えたら必ず金額を入れ直して確認してください

## 当日までのチェック

- [ ] 申込フォームから実際にテスト申込をしてみた
- [ ] 完了メールが届いた
- [ ] 領収書メールが届いた
- [ ] 参加URLが正しい（**前回のものになっていないか**）
- [ ] リマインドが予約されている
- [ ] 定員の設定（無制限にするなら「0」など、システムの仕様を確認）

## 自分用に直すところ

- 使っている申込・配信システム
- 決済サービス
- 領収書の発行元情報（会社名・住所・登録番号）
