# 講演スライドを作る

## これは何？

講演やセミナーで使うスライドを、HTMLで作ります。
PowerPointではなくHTMLで作る理由は、**あとで直すのが早い**からです。
ブラウザで見て、その場で直して、最後にPDFにします。

## こう言ってください

```
講演スライドを作ってください。
テーマは〇〇、時間は△分、聞き手は□□な方々です。
```

## ★いちばん大事な設計：結論を先に見せない

**スライドに答えを全部出してしまうと、話す前にオチがバレます。**

- 見出し（テーマ）は出していい
- **箇条書き・図の要素・結論は、クリックで1つずつ出す**
- 結論は必ず最後

### よくある失敗
「2つ目以降だけを順次表示にする」——これをやると、**見出しと1つ目の項目が同時に出てしまいます**。

**1つ目の項目も、クリックで出すようにしてください。**
最初の画面に出ているのは、**見出し（と写真）だけ**です。

### 印刷するときは全部表示
PDFにするときは、順次表示をやめて全部見える状態にします。

## レイアウトの鉄則

### 1. 下で切れない
一番多い失敗です。**最初からコンパクトに作ります**（あとで詰めるのは失敗します）。

| 要素 | 安全な値 |
|---|---|
| 見出しの文字サイズ | 1.5em 以下 |
| 要素と要素の間 | 0.3〜0.5em（1.5emのような大きな値は禁物） |
| 1枚に入れる要素 | **5つ以内** |

### 2. 文字が変なところで折れない
「岡崎 かつひろ」が「岡崎／かつひ／ろ」と3行になる、あの現象です。

- 見出し・名前・決め台詞には `white-space: nowrap` を付ける
- 改行は `<br>` で自分で指定する（ブラウザ任せにしない）
- 狭い枠に長い言葉を入れない

### 3. 全ページで文字の高さを揃える（上揃え固定）
ページごとに見出しの高さが上下すると、めくったときに文字が跳ねて見えます。
**本文のページは全部「上揃え」**にします。中央寄せしていいのは、タイトル・章扉・1文だけの演出ページだけです。

### 4. 印刷すると背景写真が消える問題
CSSの背景画像は、PDFにすると消えることがあります。
**背景写真は `<img>` タグで敷いてください。**

### 5. 文字の色を薄くしない
「グレーの文字が見にくい」は最も多い指摘です。
薄い文字色、明るい背景に明るい文字——完成後に必ず確認します。

## 作る順番（これを守ると手戻りが減ります）

1. 構成・文言・レイアウト・画像・色を固める
2. **内容が確定してから**、最後にアニメーション（順次表示）を載せる

先にアニメを入れると、直すたびに設定をやり直すことになります。

## 完成後の自動チェック（必ずやる）

目視だけでは拾えません。完成したら機械で測ります。

- [ ] 全ページ、画面から**はみ出していない**か（ギリギリも含めて検出する）
- [ ] 見出しの高さが全ページ揃っているか
- [ ] 文字と背景のコントラストが足りているか
- [ ] 最初の画面に本文が出てしまっていないか（順次表示の確認）
- [ ] 変なところで折り返していないか

## 自分用に直すところ

- 配色（自分のブランドカラーに）
- スライドのサイズ（既定は16:9）
- フォント
- 1枚目の待機スライド（別スキル「taiki-slide」参照）
